## 🆕 Ver 5.1 — A4 인쇄·PDF 페이지 분할 오류 수정

A4 검토서를 PDF로 저장하면 **표의 행이 페이지 경계에서 반으로 잘려** 인쇄되는 문제를 수정했다.
추적 과정에서 원인이 하나가 아니라 **네 가지**임을 확인했다.

> **계산 로직·수치·화면 디자인은 1바이트도 변경하지 않았다.** 변경 범위는 `@media print` 블록 · 캡처 기하 클래스 · `doSavePDF()` / `doSaveJPG()` 의 분할 로직 · 버전 문자열이다.

### 원인과 조치

| # | 증상 | 원인 | 조치 |
|---|---|---|---|
| ① | **PDF에서 표 행이 잘림** | `doSavePDF()` 가 문서 전체를 이미지 1장으로 캡처한 뒤 297 mm 씩 **기계적으로** 절단 | 행·박스 하단을 **안전 절단선**으로 수집(`collectSafeCuts`)해 그 지점에서만 캔버스를 자르도록 교체 |
| ② | **Ctrl+P 인쇄 시 백지** | `.a4-paper` 가 `.a4-overlay` 안에 있는데 `@media print` 가 오버레이를 통째로 `display:none` 처리 | `.a4-overlay.show` 만 인쇄 대상으로 전환 + 표 분할 제어 규칙 신설 |
| ③ | **마지막에 백지 1장** | `.a4-paper{page-break-after:always}` 가 `@media print` **밖**에 있어 항상 적용 | 일반 CSS에서 제거하고 인쇄 블록에서만 제어 |
| ④ | **좁은 화면에서 출력물 붕괴** | 미디어쿼리(≤840 px)로 `.a4-paper` 가 100 % 폭이 되는데 캡처는 794 px 고정 → DOM 측정값과 캔버스 레이아웃 불일치 | `.a4-capture` 클래스로 저장 시에만 794 px 기하를 `!important` 로 고정 |

④는 실측 중 발견했다. 좁은 창에서 `.a4-paper` 가 **폭 28 px · 높이 6,494 px** 로 측정됐다. 이 상태로 PDF·JPG를 저장하면 결과물이 정상일 수 없다.

### 추가한 인쇄 규칙

```css
@page{ size:A4 portrait; margin:0; }        /* 이중 여백 제거 — 210mm 축소·잘림 방지 */
table.a4-table tr{ break-inside:avoid; }    /* 행 중간 절단 방지 */
table.a4-table thead{ display:table-header-group; }  /* 2장째 표 헤더 자동 반복 */
.a4-sec-head{ break-after:avoid; }          /* 섹션 제목만 홀로 남는 것 방지 */
print-color-adjust:exact;                   /* 표 헤더 녹색·의무/조건부 색상 인쇄 반영 */
p,td,li{ orphans:3; widows:3; }
```

### 검증 — 건축물 24개 대분류 전수

연면적 60,000 ㎡ · 지상 30 / 지하 6층 조건으로 전 용도를 돌려 페이지 분할을 계산했다.

| 항목 | 결과 |
|---|---|
| 페이지 경계를 가로지르는 표 행 | **0 건** (수정 전: 의료시설 `연결송수관설비` 행 절단 확인) |
| 안전선 없이 강제 절단된 페이지 | **0 건** |
| 캡처 기하 | 전 케이스 794 px 고정 확인 |
| JS 문법 | `node --check` 통과 |

### 남은 한계

- **PDF 2장째에는 표 헤더가 반복되지 않는다.** 행이 잘리지 않는 것까지는 해결됐으나, 이미지 슬라이스 방식의 구조적 한계다. 헤더 반복까지 필요하면 PDF 생성을 텍스트 기반(jsPDF‑AutoTable 등)으로 바꿔야 한다.
- **툴바에 인쇄 버튼은 추가하지 않았다.** A4 미리보기를 연 상태에서 `Ctrl+P` 로 정상 출력된다. 버튼을 넣으면 39종 디자인 통일에서 이 도구만 어긋나므로, 통일 규격 확정 후 일괄 반영한다.

## 📦 파일 구성

```
Fire-Protection-Systems/
├── index.html          ← 메인 앱 (Ver 5.1)
├── manifest.json       ← PWA 매니페스트 (Ver 5.1)
├── sw.js               ← 서비스 워커 (CACHE_NAME = 'sobangsiseorak-v5.1')
├── README.md
└── icons/              ← 아이콘 세트 14종
```

로컬 작업 폴더에는 `_archive/` 가 함께 있으나 **업로드 대상이 아니다.**
언더스코어로 시작하므로 GitHub Pages 빌드에서도 자동 제외된다.

## 🚀 배포

1. 루트의 `index.html` · `manifest.json` · `sw.js` · `README.md` 를 저장소 루트에 업로드
   *(`icons/` 는 해시 대조 결과 무변경 — 다시 올릴 필요 없다)*
2. `Settings` → `Pages` → `Source: main branch / (root)`
3. 배포 후 **Ctrl+Shift+R** (강력 새로고침) — 설치된 PWA 는 앱 재시작
4. 화면 각인이 `MANMIN-Ver5.1` 인지 확인
5. 검토 실행 → A4 미리보기 → **Ctrl+P**: 백지가 아니라 검토서가 나오고, 표 행이 온전한지 확인
6. **PDF 저장**: 행이 경계에서 잘리지 않고, 마지막 백지 1장이 사라졌는지 확인

## 🛠️ 캐시 주의 — 이 도구는 Cache First

`sw.js` 의 fetch 전략이 **Cache First** 다.

```js
caches.match(e.request).then(cached => { if (cached) return cached; ... })
```

캐시에 있으면 네트워크를 보지 않으므로, **`CACHE_NAME` 을 올리지 않으면 기존 사용자는 수정본을 받지 못한다.**
Ver 5.1 에서 `v5.0` → `v5.1` 로 올렸고, `activate` 에서 구버전 캐시를 삭제하므로 정상 갱신된다.
다음 배포 시에도 **`CACHE_NAME` 한 줄을 반드시 올릴 것.**
